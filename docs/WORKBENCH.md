# 패턴·실험 설정·결과 조회 확장 계획

2026-09-27. 사용자가 실험 설정 프리셋과 실제 메모리 패턴 정의를 모두 원한다고 확인했다.
패턴/프리셋 파일과 CLI·GPU·CPU 대조 연결은 구현했다. 로컬 GUI의 편집·저장·단일 실행 조회도 구현했다. [사용법과 검증](GUI.md)을 참고한다.
입력 형식과 검증 결과는 [입력 문서](INPUTS.md)에 있다.

## 제출 전 결과물

CUDA 검증 엔진, Python 실험 실행기, 로컬 GUI, 테스트 및 재현 가능한 실험 기록을 묶는다.
GUI는 기존 실행기의 명령을 제공하고 기존 결과를 읽으며 검증 판정 로직을 새로 구현하지 않는다.
최종 PDF에는 실제 실험 결과와 GUI 화면, 테스트 근거를 함께 담는다.

| 구분 | 제출 전 범위 |
|---|---|
| patterns/ | 이름·설명·사용자 지정 32-bit 상수 목록을 저장한 JSON 정의 |
| profiles/ | 패턴 정의 선택, count/K/iterations, 주입 여부, timeout, 모니터링 설정을 저장한 JSON |
| results/ | 실행 시 해석한 패턴·실험 설정 사본과 해시, 코드/바이너리 정보, 원시 로그, 지표 |
| GUI: 설정 | 패턴 및 프리셋 생성·조회·편집·저장, 입력 유효성 확인 |
| GUI: 실행 | 재현 명령 제공을 우선. 실행·중단 버튼은 후순위 |
| GUI: 조회 | 과거 실행 목록, PASS/FAIL/ERROR와 원인, 설정·로그·모니터링 그래프 |
| GUI: 비교 | 다중 실행 비교 화면은 후순위. 우선 개별 실행의 조건·시간·결과 조회 |

패턴 목록 예시는 `00000000`, `ffffffff`, `12345678`, `87654321`이다.
각 값으로 전체 할당 영역을 채워 검사한 뒤 다음 값으로 넘어간다. 사용자가 입력한
상수 목록을 실제 CUDA fill/verify와 CPU 대조가 처리해야 하며, GUI에만 저장하는 기능으로 끝내지 않는다.
임의 바이너리 파일 업로드, 사용자 스크립트 실행, index/seed 생성 규칙은 후속 확장으로 둔다.

GUI에서 정의 파일을 생성하는 기능과 메모리 데이터 자체를 생성하는 CUDA 커널을 구분한다.
거대한 배열 파일 대신 생성 정의를 저장하고, 실행 당시 정의 내용도 결과에 복사하여
나중에 프리셋을 편집해도 과거 실험의 의미가 바뀌지 않게 한다.

## 구현 시 확인할 계약

- 기존 네 패턴 기본 실행과 정상/주입/오류 종료 코드를 유지한다.
- 실행 완료 판정은 고정 숫자 4 대신 실제 패턴 수 × 반복 횟수를 사용한다.
- 주입은 첫 반복의 첫 번째 패턴 실행에만 적용한다. 값이 같다는 이유로 여러 번 주입하지 않는다.
- 사용자 지정 상수, 첫 값이 0이 아닌 목록, 목록 길이 변경, 잘못된 32-bit 값, 빈 목록을 검사한다.
- GPU 기록·CPU 대조의 expected 값과 출력이 실제 선택한 패턴을 따른다.
- CLI와 GUI가 같은 설정 검증·실행 경로를 사용한다.
- GUI의 N/A·수집 실패·중단 표시는 원본 실험 기록의 의미를 유지한다.
- GUI의 실행 상태 표시는 프로세스 상태다. 커널 진행률이나 iteration별 실시간 결과는 현재 엔진에서 제공하지 않는다.
- 상세 오류는 우선 원시 로그로 조회한다. 위치별 집계 표를 추가하려면 구조화 결과를 별도로 설계한다.

## 순서와 시간 배분

1. 현재 검증된 버전에서 큰 배열 기준 실험과 동일 조건의 성능 비교 한 건을 수행한다.
2. 패턴/프리셋 파일과 CLI 실행 연결, 관련 회귀 검사를 구현한다(2시간 예산).
3. 최소 로컬 GUI를 구현한다(1시간 예산). 패턴/프리셋 편집과 결과 조회를 우선한다.
4. 최종 실행·결과 대조 후 화면과 측정 결과를 README/PDF에 반영한다.

사용자 확인에 따라 PyTorch 실습 2시간을 선택 과제로 유지하고 GUI 범위를 축소한다.
실행·중단 버튼과 여러 실행 비교 화면은 여유 시간에 추가한다. 면접 연습에서 옮긴 1시간을 GUI에 배정한다.
오늘의 README/자료 뼈대 2시간은 패턴/프리셋 구현으로 옮기며 문서화는 해당 구현 및
내일 PDF 제작에 포함한다. 성능 실험·PDF 3시간·지원서 확인·제출·예비 예산은 유지한다.
시간 초과 시 GUI 비교 기능과 실시간 실행 편의 기능부터 줄이고 설정 저장·결과 조회를 우선한다.
범용 패턴 생성기나 별도 서비스/DB 구축으로 확대하지 않는다.

## 구현 완료 기록 — 2026-09-27

패턴/프리셋 생성·편집·저장과 명령 복사, 과거 실행 검색·상태·원시 기록·GPU 지표 조회를 구현했다.
CLI와 같은 입력 검증을 사용하고, 읽을 당시의 파일 해시로 저장 충돌을 확인한다.
서버 테스트 6개와 Chromium 브라우저 검사 9개를 통과했다. 브라우저 테스트는 실제 저장된
128 MiB 결과를 복사해 조회하고, 임시 공간에만 편집 파일을 저장했다.
실행·중단 버튼, 다중 실행 비교, 실시간 진행률은 이번 기본 범위에 포함하지 않았다.
9/27에 선택 과제 [PyTorch 실습](PYTORCH.md)도 완료했다. 제출 버전 확인과 자료 정리가 남아 있다.

# 제출 버전 확인

추가 진단 코드 `a25a1b9`에서 Sanitizer 대조 16개, CUDA 타임라인 2건을 확인하고
기존 CTest 46개를 재실행했다. 수집 누락 거부 대조 5개도 통과했다.
실행 조건과 변경한 호스트 설정은 [진단 실험](DIAGNOSTICS.md)에 있다.
검증 코어의 알고리즘은 아래 전체 검사 이후 변경하지 않았다.

2026-09-28 KST, 코드 `9bda52f1fe5d13be5c90fc78b6132299490eba78`에서 아래 검사를 모두 통과했다.
시작 시 작업 트리는 깨끗했으며 검사 전후 추적 파일의 SHA256이 일치했다.
이 전체 검사의 원시 기록은 보존하며, 이후 추가한 진단의 범위는 위에 별도로 명시했다.

CPU 전용 빌드는 새 디렉터리에서 생성하고 CUDA 프로그램은 clean build로 다시 빌드했다.
PyTorch 확장은 기존 빌드와 소스 해시를 보존하고 실제 GPU 검사를 다시 실행했다.
환경은 RTX 3060 / WSL2 Ubuntu 22.04 / CUDA Toolkit 12.8 / PyTorch 2.10+cu128이다.

## 포트폴리오에 사용하는 실험

다음은 이번 재검사와 별도로 수행한 실험이다. 원시 결과와 문서 수치의 일치를 확인했으며,
이번 코드에서 성능 비교·10분 부하·DCGM을 다시 측정한 것으로 표현하지 않는다.

- [성능 비교](PERFORMANCE.md): 고정된 전후 버전에서 호스트 버퍼 재사용으로 전체 실행 시간 중앙값 40.9% / 43.1% 감소.
- [반복 읽기](LOAD.md): 256 MiB, 609.94초, GPU 검사 409,600회와 CPU 전체 대조 400회. 지표 수집은 579/581회 성공.
- [CUDA 연산 디버깅](LAYOUT.md): stride 무시 결함 재현, 두 수정 방식과 입력 배치별 실행 비용 비교.
- [DCGM 실행](DCGM.md): 장치 검색·지표 수집 성공, Level 1 배포 환경 검사 실패와 원시 원인 기록.

## 입증 범위

이 프로젝트는 GPU 검증 소프트웨어의 구현·오류 재현·독립 대조·측정 및 재현 조건 보존을 보여준다.
RTX 3060의 GDDR6 환경에서 수행했으며 HBM 제품 검증이나 전체 VRAM·장기 신뢰성 인증이 아니다.
소프트웨어 XOR 주입은 물리 결함 재현이 아니다. Compute Sanitizer의 완료 범위는
위 추가 진단 조건에 한정된다. DCGM 고급 진단, ECC/XID 분석, 드라이버 수정,
온도 의존성 규명은 수행하지 않았다.

제출용 코드·검증 증거는 확보했다. 지원서 입력, 첨부 PDF 제작·확인, 채용 사이트 접수는 별도 작업이다.
